# KPI — Software

**Secteur (comprendre) :** [[Technology & Telecom]]
**Analyses d'entreprise liées :** [[SaaS Company - Analyse]]

50 indicateurs clés pour ce secteur (source : Umbrex Library of Industry-specific KPIs).

| KPI | Description |
|---|---|
| Active Users | This can be segmented into daily active users (DAUs), weekly active users (WAUs), and monthly active users (MAUs). These metrics can provide insight into user engagement and the 'stickiness' of a software product. |
| API Calls | For software companies with integrations, the number of API calls can indicate usage and reliance on the software. |
| API Performance | For software that relies on API interactions, this KPI measures the performance of those APIs in terms of speed, error rates, and uptime. |
| Average Revenue Per Paying User (ARPPU) | This KPI measures the average revenue received from each user who pays for the software. It's especially relevant to software companies that offer freemium models or tiered pricing structures. |
| Average Update Adoption Time | This measures the average time it takes for users to adopt an update after it's released. |
| Bounce Rate | For web-based software or platforms, this measures the percentage of users who leave the website after viewing only one page. A high bounce rate may indicate poor user interface or experience. |
| Cloud Downtime | For cloud-based software, this is the amount of time when the service is unavailable to users. Minimizing downtime is crucial for maintaining user trust and satisfaction. |
| Code Commits | This is the number of times developers make changes to a software's source code. While not a business KPI, it can help gauge the speed of product development and enhancements. |
| Code Coverage | A measure of the amount of application code that is 'covered' by automated tests. High coverage can be indicative of a lower likelihood of undiscovered bugs and a high quality of code. |
| Code Deployment Frequency | This is the frequency at which new code is pushed to production. Higher frequency could indicate a strong focus on continuous delivery and agile development. |
| Code Review Efficiency | In a software development context, this refers to the speed at which peer code reviews are conducted. Delays here can slow overall development speed. |
| Code Velocity | This measures the speed at which code is being written, indicating the pace of development. This may provide insight into how quickly a software company can innovate or respond to issues. |
| Conversion Rate from Trial to Paid Users | This KPI is especially applicable to software companies that offer a trial period for their product. It measures the percentage of users who switch from a free trial to a paid subscription. |
| Cost Per Bug | This measures the average cost of fixing software bugs and can be a good indicator of software quality and development efficiency. |
| Data Breach Incident Rate | For software companies dealing with sensitive user data, this KPI measures the frequency of incidents where unauthorized parties gain access to secure data. |
| Deferred Revenue Growth | For subscription-based software companies, this is the revenue that is collected upfront but not yet recognized. A high growth rate indicates strong future revenue potential. |
| Expansion MRR Rate | This measures the additional monthly recurring revenue from existing customers through upselling or cross-selling. A high rate indicates good account management and product value. |
| Feature Adoption Rate | This KPI measures how quickly new features are adopted by users after being launched. High rates may suggest that the new features are meeting customer needs effectively. |
| Feature Request Count | This measures the number of user-generated requests for new features. While user feedback is important for all software companies, this KPI is particularly relevant to those operating in fast-evolving markets where user needs and expectations can change rapidly. |
| Free to Paid Conversion Rate | This KPI is especially relevant for freemium software companies and shows the percentage of free users who convert to a paid subscription. |
| In-app Purchase Revenue | This is particularly important for mobile and gaming software companies. It represents the revenue earned from purchases made by users within the application itself. |
| Installation Failure Rate | This KPI measures the number of software installations that fail as a percentage of total installation attempts. |
| License Revenue vs. Subscription Revenue | For software firms selling both licenses and subscriptions, tracking the ratio of these two can show a shift in a company's business model. For instance, an increase in the proportion of subscription revenue indicates a move towards a Software-as-a-Service (SaaS) model. |
| Mobile vs Desktop Users | For software companies that offer both desktop and mobile versions of their product, this KPI provides insight into user behavior and preferences. |
| Number of Customer Logins | For certain software products, especially those designed for frequent use (e.g., productivity tools), tracking the number of customer logins can help gauge the level of user engagement and dependency. |
| Number of Customizations/Configurations | For customizable software, this KPI measures the average number of customizations or configurations made by users. A higher number could indicate that users find the software flexible and adaptable to their needs. |
| Number of Platform Integrations | For SaaS businesses, this refers to the number of integrations with other software or platforms. A higher number of integrations can make the software more valuable to users. |
| On-Premises vs Cloud Revenue | Similar to License vs Subscription Revenue, this metric monitors the transition between different software delivery models, indicating a company's progress in adapting to cloud technology trends. |
| Peak Concurrent Users | In gaming or real-time collaboration software, this is the highest number of users online and using the software at the same time. |
| Percentage of Revenue from Partnerships | In the software industry, strategic partnerships can play a significant role. This KPI measures the proportion of total revenue that comes from such partnerships. |
| Percentage of Users on Latest Version | For software companies that regularly roll out updates or new versions, this KPI tracks the percentage of users who are on the latest version. |
| Ratio of Active to Registered Users | This ratio provides an indication of user engagement, showing what percentage of registered users are actively using the software. |
| Ratio of Freemium to Paid Users | For software companies that offer freemium models, this ratio can provide insights into conversion efficacy and the perceived value of premium features. |
| Revenue from International Markets | This KPI shows the proportion of a software company's revenue that comes from outside its home market. A higher percentage might indicate successful international expansion. |
| Revenue Per User (RPU) | This KPI measures the average revenue generated per user, indicating the value derived from each user. |
| SaaS Quick Ratio | For software-as-a-service companies, the Quick Ratio measures the company's growth efficiency by comparing the addition of recurring revenue to the loss of recurring revenue. |
| Security Breach Count | This KPI tracks the number of security breaches that a software company has experienced over a given period. Frequent breaches may indicate weaknesses in the software's security infrastructure. |
| Server Response Time | For web-based and cloud-based software, this measures how long it takes for the server to respond to a user's request. Faster response times can lead to a better user experience. |
| Session Duration | This KPI measures how long users interact with the software during a single visit. Longer sessions can indicate higher engagement levels. |
| Software Boot Time | This is the time it takes for the software to start up or load. Faster boot times typically lead to a better user experience. |
| Software Crash Rate | This measures how frequently the software crashes while users are utilizing it. A lower crash rate indicates better software stability and user experience. |
| Software Dependency | For businesses offering development tools or platforms, this measures how many other applications or pieces of software depend on their software to function. |
| Software Interoperability | A measure of how well the software works with other software systems. High interoperability can increase the software's utility to users. |
| Software Utilization Rate | For companies selling to enterprise clients, this KPI measures the percentage of purchased software licenses that are actively being used. Underutilization can suggest a lack of fit with client needs. |
| Stickiness Ratio (DAU/MAU) | This ratio provides an indication of user engagement, showing what percentage of monthly users are using the software on a daily basis. |
| Support Tickets | This is the number of customer support requests received. A high number of tickets can indicate potential issues with software usability or stability. |
| Technical Debt | This KPI measures the estimated cost of additional rework caused by choosing a quick, easy solution now instead of a better approach that would take longer. High technical debt can hamper future development speed and software stability. |
| Third-party Integration Performance | This measures the performance and reliability of integrations with third-party software. Poor performance here can impact the user experience and overall value of the software. |
| Time Spent in App per User | This metric shows the average amount of time a user spends in the software per session or over a certain time period. Higher numbers can indicate greater user engagement. |
| User Collaboration Rate | For software designed for collaboration, this KPI measures the frequency and intensity of collaboration events, such as shared documents, joint editing sessions, etc. This can help assess the software's effectiveness as a collaboration tool. |
